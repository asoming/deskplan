# 本机优先的更新顺序

用户已明确要求：“更新阿每次更新肯定是我先用阿”。

每次修改先在隔离显示环境完成测试并构建本机安装包，然后备份数据与旧程序、更新本机日序并重启日序供用户使用，再同步或安排 GitHub 发行。不要仅交付下载链接让用户自行升级。用户已授权这一更新流程中的日序重启；不应再把更早的“不打扰工作”解释成禁止更新重启。

“不打扰工作”仍适用于日常运行和开发测试：后台不抢焦点、不强制置顶，GUI 回归使用隔离显示或 CI，不操作其他工作应用。若出现新的、具体的数据风险，先处理风险。日序的任务数据与个性化设置要保留，用户明确要求变更的设置除外。

升级版本号时只修改 package.json 的 version、package-lock.json 的顶层 version 和 packages[""].version；不要全局替换依赖包的版本号。
